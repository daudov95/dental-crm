# DentalCRM

Модульная веб-ориентированная CRM-система для малых стоматологических клиник. Предназначена для единого учета обращений пациентов, ведения воронки сделок, сопровождения длительных курсов лечения (ортодонтия, имплантация), планирования расписания врачей, контроля оплат и рассрочек, а также формирования управленческой аналитики.

## Стек технологий

- **Backend:** PHP 8.5, Laravel 13
- **Frontend:** Livewire, Tailwind CSS, Alpine.js
- **База данных:** PostgreSQL 17
- **Кэш, очереди и планировщик:** Redis 8.4, Laravel Queues, Laravel Scheduler
- **Веб-сервер:** Nginx 1.28
- **Инфраструктура:** Docker, Docker Compose, GNU Make

## Архитектура

Приложение спроектировано в парадигме **модульного монолита (Modular Monolith)** с элементами DDD (паттерн Actions, Readonly DTO, межмодульное взаимодействие через доменные события). Бизнес-домены изолированы в директории `modules/` и подключаются через автозагрузку PSR-4:

```text
modules/
├── Identity/     # Сотрудники, аутентификация, ролевая модель (RBAC), политики доступа
├── Patients/     # База пациентов, каналы привлечения, фиксация согласий по 152-ФЗ
├── Catalog/      # Справочник стоматологических услуг, категории, цены, длительность
├── Deals/        # Воронка сделок (Канбан и список), планы лечения, причины отказов
├── Scheduling/   # Расписание врачей, проверка пересечений, напоминания на завтра
├── Billing/      # Учет оплат, рассрочек, пересчет остатка долга, контроль просрочек
├── Analytics/    # Read-only дашборд руководителя: KPI, конверсия, экспорт в CSV/Excel
└── Audit/        # Журнал аудита действий пользователей (152-ФЗ) на базе событий
```

### Ключевые архитектурные принципы
- **Изоляция модулей:** модули не изменяют напрямую модели других доменов.
- **Событийное взаимодействие (Event-Driven):** кросс-модульные операции (например, запись платежа в журнал аудита или обновление финансового статуса сделки) выполняются через доменные события Laravel.
- **Фоновая обработка:** выделенные контейнеры `queue` и `scheduler` ежедневно проверяют просроченные платежи по рассрочкам и формируют список пациентов для напоминаний о завтрашних визитах.
- **Универсальность конфигурации:** наименование конкретной клиники вынесено в переменную окружения `CLINIC_NAME` в файле `.env`.

## Ролевая модель доступа (RBAC)

- **Руководитель (`director`):** полный доступ ко всем разделам, управление персоналом и справочником услуг, KPI-аналитика, экспорт отчетов и просмотр журнала аудита.
- **Администратор (`admin`):** ведение базы пациентов, регистрация обращений (Instagram, WhatsApp, Telegram-бот, 2ГИС, телефон, рекомендации), работа с Канбан-доской сделок, запись в расписание, прием оплат и отработка уведомлений о просрочках.
- **Врач (`doctor`):** просмотр собственного расписания, карточек закрепленных пациентов и связанных сделок, обновление статусов проведенных визитов и ведение заметок по этапам лечения.

## Быстрый старт (Docker)

### Предварительные требования
- Docker и Docker Compose
- GNU Make (для удобного запуска команд)

### Установка и запуск

1. Клонируйте репозиторий и создайте файл окружения:
   ```bash
   git clone <repository-url> dental-crm
   cd dental-crm
   cp .env.example .env
   ```

2. Соберите образы и запустите все 6 контейнеров (`app`, `nginx`, `postgres`, `redis`, `queue`, `scheduler`):
   ```bash
   make build
   ```

3. Выдайте права на директории кэша/логов, установите зависимости и сгенерируйте ключ приложения:
   ```bash
   docker compose exec app chmod -R 777 storage bootstrap/cache
   make composer c="install"
   make art c="key:generate"
   ```

4. Примените миграции и наполните базу тестовыми данными:
   ```bash
   make fresh
   ```

5. Откройте приложение в браузере:
   ```text
   http://localhost:8080
   ```

## Основные команды Makefile

| Команда | Описание |
| --- | --- |
| `make up` / `make down` | Запустить / остановить контейнеры |
| `make build` | Пересобрать образы и запустить проект |
| `make ps` | Проверить статус всех сервисов |
| `make sh` | Войти в bash внутри контейнера PHP (`app`) |
| `make psql` | Открыть консоль PostgreSQL (`psql`) |
| `make redis` | Открыть консоль Redis (`redis-cli`) |
| `make logs-queue` | Просмотр логов воркера очередей Redis |
| `make logs-scheduler` | Просмотр логов планировщика задач |
| `make art c="..."` | Выполнить любую команду `php artisan` |
| `make composer c="..."` | Выполнить команду `composer` |
| `make fresh` | Пересоздать БД и запустить сиды |
| `make test` | Запустить автотесты |
| `make clear` | Очистить кэши Laravel |
